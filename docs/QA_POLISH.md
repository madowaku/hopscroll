# QA · claude/polish-mobile (Issue #2)

## 変更点
- 360×640の論理フレームを丸ごと拡大縮小（`--fit`）。720×1280でもUIが小さくならず、Canvasは端末DPR（最大3）で描画するのでぼけない。
- ウサギ約34%縮小（0.68→0.45）、左寄せ（x=52）、世界の縮尺0.82→0.74で先の見通しを拡大。HOPリングはHUD下へ移動。
- 着地予測：残りジャンプの点線軌道＋着地リング。押す/離すで即座に再計算。色と表示：緑NEXT／赤MISS!（×印）／金GOAL!。もう一方の速度での着地点を薄いリングで表示。
- ゴール：チェック柄の着地パッド、柱、チェック柄バナー、旗、下向き矢印「LAND HERE」。
- 星：放射状の光と白い芯、脈動。取得時にリング・火花・「+★」・2音のチャイム。月は淡色化し、金色は星とゴール専用に。
- Stage 1チュートリアル：切替えると着地が良くなるときだけボタンが脈動し「▼ HOLD NOW!」「LET GO!」を表示。他ステージも3回失敗すると同じ補助が出る。
- 入力：ボタンに加えて画面（Canvas）押下でもFAST。指・キーごとに追跡（マルチタッチで固着しない）。pointercancel／lostpointercapture／blur／visibilitychange／pagehide／リトライで解除。長押しメニュー抑止。アプリ切替で一時停止しRESUME。
- 演出：FAST切替の風切り音、離陸・着地のスカッシュ、FAST時の前傾と流線、着地の砂ぼこり、クリア時の紙吹雪と喜び顔、落下アニメ後に結果表示。
- ミュートボタン（M キー）、モーダルはSpace/Enterで操作可能。`prefers-reduced-motion`で揺れ・粒子・フラッシュを停止。

## 2026-10-30 Codex core #3 統合後の失敗理由 UI 連携
- `onFail()` は `state.failure` を参照し、ゴール通り越し・足場の縁・足場間の穴・プラットフォーム手前/通り過ぎを区別する。
- `failure.correction` は「最近傍の安全な足場へ寄せる方向」であり「ステージ正解への誘導」ではないため、UIに断定的な FAST/SLOW 助言は出さない。
- `state.failure` が無い場合も従来の一般的なリトライ説明へフォールバック。
- ブラウザ実操作とAndroid実機で、失敗位置と案内文が一致するか確認する（以下はまだ未検証）。
