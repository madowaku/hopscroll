# Moon Lab UIレビュー v0.1

設計方針：**不要なセカンダリラベルや説明を避ける。レイアウトに説明させる。**

## 変更前の試遊問題（ユーザー実機スクリーンショット）
- 画面上部に「HOPSCROLL / MOON LAB」「速度で、道をつくる。」「003 月光橋」「しずかな月光橋」と何重にも見出しがある。
- HOP、月印、SLOWで橋が光る、SLOW ONLY、NEXT、画面外の補足文、画面下のHOLD説明が同時に主張する。
- 失敗カードが足場・着地位置を覆い、直後に何を直せばよいか視覚的に見られない。
- 画面下の説明と二重のボタン類が、遊びのための空間を圧迫する。

## 採用した情報の優先順位
1. **盤面**：キャラ、着地リング、通常床・月光橋、穴、ゴール。
2. **主入力**：大きなHOLDボタンひとつ。リリースでSLOW。キー・タッチ操作は同じ。
3. **局所フィードバック**：失敗地点の赤リング、短い原因、月印からの再試行。
4. **補助**：月印／団子は取得後のみHUDへ。ヘルプ／音／一時停止は小ボタン。

## 具体的な差分
- 大見出し削除、2ステージの小さなタブ化。操作／音ボタンを上部にまとめる。
- HUDは盤面の上に重ね、HOP以外の未取得情報を隠す。月印／団子は獲得した時だけ表示。
- SLOW ONLY連発を排し、橋は実体化・点線で表現。FASTで見える最初の橋にだけ「離して着地」。
- レベル名のCanvas重複描画を止める。
- 開始／中断／結果を盤面上部の小カードにし、水平レーンと着地情報を覆わない。
- 失敗カードは「橋が消えた！」「飛び越した！」等を主体にし、修正ヒントを一行へ。
- #hintは常時表示せず、スクリーンリーダー向けライブ領域として維持。#demoは導入時の触れる見本として維持。
- #resumeは月印復帰時だけ出す。「SLOWで再開」。
- スコア／物理／月印判定／音声判定に変更なし。

## 受け入れ（CIと人間）
- [ ] GitHub Actionsの3画面サイズ (320×700 / 360×640 / 720×1280) でHOLDが表示範囲内。
- [ ] Introと失敗カードは画面下のレーンを覆わない。テストで上部への収まりをチェック。
- [ ] Chromeで初回開始、FAST↔SLOW、橋失敗、月印復帰、二股、ゴールの操作に回帰なし。
- [ ] Androidで画面押下・ボタン押下・復帰後の操作固着なし。
- [ ] キャラの顔・耳・団子が小画面でも読める。**ミチルは別ブランチのため、このUI PRには未統合**。

## 注意
表示面積を節約するために必要な情報まで消してはいけない。初見プレイヤーが橋を理解できなかった場合、説明文の常時追加ではなく**最初の橋の短いインタラクティブな見本**を優先する。
