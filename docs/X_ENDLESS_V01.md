# HOPSCROLL / X ENDLESS v0.1 — ちびミチルの月夜ホップ

2026-10-31 / 提案仕様。実装前のデザイン基準であり、まだ完成・公開ではない。

## 目指す体験（MDE）
- Xで流れてきた一枚を見て「何これ、遊びたい」と思う。
- リンクから数秒以内に開始、片手長押し/離すだけで遊べる。初回は最初の3ホップで操作を実感する。
- ミス時に「あと1回」と思う。失敗位置と着地予測のズレが見え、再挑戦は1タップ。
- 20〜40秒程度の典型的な短い勝負を想定（人間の試遊で調整）。うまい人のプレイに上限なし。
- スコア画像のキャラやセリフが少しずつ変わり、記録と一緒にXへ見せたくなる。

## 2本立ては厳守
- itch.io: Moon Journey（ミチル、既存6ステージ）、独立して維持。
- X: /star-run.html を継承してエンドレス化。既存24ホップ版はリグレッション用に保存。
- 既存 core.mjs の PERIOD=0.78s、SLOW=105px/s、FAST=270px/s、「ジャンプは自動で世界速度のみ操作」を変更しない。
- 本編・既存スプライト・配布ZIP・公開先はこの仕様作成時点で変更しない。

## キャラ: ちびミチル
Flappy Birdから遠目で読めるシルエット、Snakebirdから素朴で誇張できる表情だけを学び、固有の造形をコピーしない。
- 月兎娘ミチルの同一人物を3頭身未満にデフォルメ。もちのような丸顔と小さい胴体、大きな片方だけ曲がった耳、点目、特徴的な短い衣・三色団子。
- 48px級の実プレイ表示でも区別できる。白/薄藤の本体+暗色輪郭+団子の差し色。背景とのコントラスト、色覚差を確認。
- 予備動作で耳を前に、飛翔中は耳が後ろへ、着地時は縦につぶれ、失敗時は耳がへにゃっと落ちる。強い揺れは低減モーション設定で抑制。
- 団子を拾うたびに「団子のしっぽ」が伸びる【装飾のみ】。当たり判定と操作難度を変えない。長すぎる場合は小さな星/束で省略。
- 外見は独自制作を前提とする。Flappy Bird/Snakebirdの画像や音を流用しない。

## ルール
- 長押し=FAST、離す=SLOW。画面内のミチルのXは固定、月の足場が左へ流れる。
- NEXT着地点を一目で読める表示。ミスの瞬間は理由・失敗位置が分かる短い演出、その後リトライ。初回は最初の3ホップを安全にし、必要なら１回だけ「押すと速い / 離すと遅い」。
- 旧STAR RUNの固定24ホップ終端を撤去。スクロールで先を継ぎ足し、画面外の古い地形を破棄する。見た目と判定が一致する足場のみ採用。
- 基本スコアは **HOPS = 成功した着地数**。団子は別表示（同HOPSの参考記録/演出）で、生存のための必須条件にしない。死んだジャンプ・空中通過は加点しない。
- 既存GATESとSTARsは旧版のテストに残すが、X版の主表示はHOPS/BEST、団子は小表示。リーダーボードなしでも遊べる。
- ノーチェックポイント、落ちたら終了。1タップで即再開。BGMなしでも快いオリジナルSE。サウンドOFF、操作固着対策、バックグラウンド停止とSLOW再開。
- 段階的な変化: 1–5 HOPS: 学習、6–15: SLOW/FAST切替、16–30: 幅/間隔に変化、31+: たまに息継ぎを挟む。難度は急上昇より変化を優先。

## エンドレス地形生成
- 初版は任意乱数で足場を置かず、「着地が検証済みの6〜12ホップの小節（motif）」を複数用意してseedで接続。候補をリアルタイム生成する際にも実物理で検証。
- 小節の境界には十分広い安全床を配置し、入口の実際の位置・速度履歴によって詰む接続を防ぐ。生存可能性を全経路一律に保証できないなら妥当なプレイ状態分布を列挙して検証し、危険な接続を生成しない。
- 30/60/120/144Hzと切替タイミング±50msで少なくとも参照ルートの余裕を確認。常時FAST/常時SLOWの単純な最適解が続かないかも検査。
- スコア稼ぎ目的の停止・重複評価は不可。地形、団子、スコアはseedで再現可能。生成済み区間の整合性を保ちながら先読み描画。
- seedによる同一コースの公平性を第一にし、「たまたま詰んだ」はバグ扱い。

## X向け共有
- モードA「今日の月道」: JST日付から導く全員同じseed。別の日は切り替わる。URLに mode=daily&date=YYYY-MM-DD を持たせ、リンクを押すと同じコースで遊べる。
- モードB「FREE RUN」: プレイごとのseed、共有リンクで同じ条件に挑戦できる。
- 結果画面: 大きく HOPS、自己BEST、団子数、「あと一歩だったのに」等の短いラン由来のセリフ、ちびミチルの表情、再挑戦、共有。
- ボタン「Xに投稿」は intent/tweet で記録文＋ゲームURLを下書きとして開く。投稿自体はユーザー操作。画像は添付されない点をUIで明示。
- 別ボタン「スコア画像を保存/共有」は Canvasで1080x1350程度のPNGを作る。Web Share Filesが使える場合は共有を提案、使えない場合は画像保存/コピー。X投稿への画像自動添付を保証しない。
- Xリンクカード用に固定1200x630のOGP画像を用意。twitter:card=summary_large_image、og:title、og:image等は公開HTMLに設定。各個人のスコアをカードに動的反映するのは初版の範囲外。
- 自己記録はlocalStorage等で端末内保存。スコアの公正な公開ランキングやアカウント登録、外部トラッキングは初版に含めない。
- X投稿文例: 「HOPSCROLL 🌙 37 HOPS。38回目で月に帰った。今日の月道、越えられる？ [URL] #HOPSCROLL」

## 実装順（依存関係）
1. STAR RUN 24ホップ版を維持しつつ、別モジュールでseed付き無限地形/スコアを実装。実物理のソルバーと回帰テストから着手。
2. 既存 /star-run.html へX用モード切替と簡潔UIを実装。ゲーム起動→死→1タップ再開、スマホ長押し・pointercancel・背景復帰をブラウザテスト。
3. ちびミチルの縮小シルエットと着地/失敗表現を載せる。装飾の団子しっぽはヒットボックス非干渉。スコア画像の見栄えを320px画面とX投稿画像で確認。
4. 日本語/英語、固定OGP、投稿intent、結果PNG、JST日替わりseedとURL検証を追加。
5. 実機AndroidとXの実投稿下書き/リンクカード、10人前後の人間試遊を経て難度・UIを調整。デプロイ/公開は別の判断ゲート。

## 合格条件
- 初見に説明しなくても操作を発見でき、少なくとも3回の着地を体験できる。
- 無限区間でメモリ/描画負荷が無制限に増えない。再挑戦時に入力がFAST固着しない。
- 100以上のseedで進行ルート検証。30/60/120/144Hzで判定・スコアが一致。悪いseedは記録して再現できる。
- 30 HOPS以上の実プレイの録画/目視チェック。死んだ位置とNEXT表示が一致する。
- 片手の小画面（320px幅）で主要ボタン、SCORE、再挑戦、共有が見える。
- 外部ログインなしで遊べる。X投稿は明示操作、共有画像/URLの内容に矛盾がない。
- 「遊んだ後に誰かへ見せたくなるか」を人間に聞く。単にCIが通っただけでは公開しない。
